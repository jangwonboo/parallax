# 한국어 톤앤매너 — 형용사 대신 축

"소설처럼 써줘"는 지시가 아니라 기분이다. 같은 프롬프트를 두 번 돌리면 다른 결과가 나온다. 이 스킬은 문체를 **여섯 축의 고정값**으로 정의하고, 프롬프트에는 형용사 대신 그 축을 넣는다.

축 값은 서술이 아니라 **검사 가능한 문장**으로 쓴다. "자연스럽게"는 검사할 수 없고 "60자 넘으면 끊어라"는 검사할 수 있다.

## 쓰는 법

1. 아래 표에서 문체를 고른다. 자세한 명세는 [`references/registers.md`](references/registers.md).
2. 그 register 절의 축 목록을 **그대로** 시스템 프롬프트의 `[문체 사양]` 블록에 붙인다.
3. 결과를 기계로 검사한다 — 특히 `nominal`은 [`scripts/check_endings.py`](scripts/check_endings.py).

```bash
python scripts/check_endings.py 초고.md            # -다로 샌 문장 보고
python scripts/check_endings.py 초고.md --quiet    # 개수만, 누출 있으면 exit 1
```

| register | 종결 | 문장 분할 | 어휘 | 대명사 | 쓰임 |
|---|---|---|---|---|---|
| `literal` 직역 | -다 | 원문 유지 | 원어 근접 | 명시 | 대조 확인, 학술 |
| `fiction` 소설 | -다 (평서) | 적극 분할 | 고유어 우선 | 대폭 생략 | 소설, 서사 논픽션 |
| `essay` 에세이 | -다 | 중간 | 균형 | 생략 | 에세이, 교양서 |
| `business` 비즈니스 | -습니다/-다 | 적극 분할 | 한자어 | 생략 | 보고서, 실용서 |
| `newneek` 뉴닉 | -요 해요체 | 최대 (40자) | 일상어 | 생략 · '우리' | 교양서를 쉽게 |
| `nominal` 개조식 | **명사형** | 원문 유지 + 단락 내 축약 | 한자어 | 생략 | 보고서식 통독, 발췌 |

한국어는 영어와 달리 주어와 대명사를 계속 쓰지 않는다. `he said`·`she thought`·`it was`를 매번 "그는"·"그녀는"·"그것은"으로 옮기면 그 자체가 가장 큰 번역투 신호다. **대명사 축이 품질을 가장 크게 좌우한다.**

## 문체 규칙을 프롬프트에 넣을 때 — 흩지 마라

**한 문체의 핵심 규칙은 반드시 한 자리에 모아 둔다.** 강조하려고 여러 자리에 되풀이하면 강조가 아니라 희석이 된다.

실측: `nominal`의 종결 규칙을 축 하나에 압축했을 때 36블록·171문장에서 `-다` 누출이 **1건**이었다. 같은 규칙을 계사문 처리·청유형 처리까지 별도 축으로 쪼개고 [절대 규칙]에까지 승격했더니 **54건**으로 늘었다(시스템 프롬프트 29.4k→33.3k 토큰). 압축형으로 되돌리자 다시 잡혔다.

## 문체는 실행마다 흔들린다 — 기계 검사를 붙여라

같은 프롬프트로 같은 원문을 세 번 돌렸을 때 `nominal`의 누출이 1건 → 15건 → 1건이었다. 프롬프트만으로는 문체가 보장되지 않는다.

**누출은 긴 문단의 가운데에 몰린다.** 1,200자 12문장짜리 문단은 앞뒤가 규칙대로인데 중간 여섯 문장이 풀린다. 모델이 긴 서사에서 규칙을 놓치는 자리다.

그래서 순서는 항상 **① 문체 사양으로 생성 → ② 기계 검사 → ③ 걸린 대목만 재요청**이다. 3단계는 재작성이 아니라 **그 부분만** 갈아 끼우는 것이다 — 전체를 다시 쓰게 하면 문체 말고 다른 것이 함께 바뀐다.

## 개조식(`nominal`)

이 스킬에서 가장 손이 많이 간 문체다. 전용 문서: [`references/nominal.md`](references/nominal.md).

문장이 한자어 동사성 명사로 끝난다.

| 흔한 실수 | 개조식 |
|---|---|
| 두 부분으로 구성됨. | 두 부분으로 **구성**. |
| 설명을 제시함. | **설명 제시**. |
| 폐기가 필요함. | **폐기 필요**. |
| 제거하는 시도를 함. | **제거 시도**. |
| 광범위한 출처에서 도출됨. | 광범위한 출처에서 **도출**. |
| 가능성이 높다. | 가능성이 **높음**. (마땅한 한자어가 없을 때만 고유어 명사형) |
| 오랫동안 탐구해왔다. | 오랫동안 **탐구해왔음**. (시제·상을 실을 때만 `했음/할 것임/고 있음`) |
| 동기는 공백. | 동기는 **공백에 해당**. (계사문을 체언 하나로 뚝 끊지 않는다) |
| 안나라고 가정해 보자. | 안나라고 **가정할 경우**, … (청유형 도입부는 조건절로) |

**인용부호 안은 건드리지 않는다.** 대사는 인물이 실제로 한 말이라 개조식으로 바꾸지 않는다. 검사 스크립트도 인용구를 마스킹한다 — 그러지 않으면 그 문장이 영원히 "아직 누출"로 남는다(규칙대로 손대지 않으므로 재요청해도 그대로다).

**소설에는 쓸 수 없다.** 대사가 전부 무너진다.

## 번역투 제거(deslop)와의 관계

번역투 제거는 문체 지정과 **다른 패스**다. 섞으면 둘 다 나빠진다. 그리고 강도는 문체마다 다르다 — 문체 자체가 규칙인 곳에 세게 걸면 문체가 지워진다.

| register | deslop 강도 |
|---|---|
| `literal` | 약 (직역체는 의도된 것이다) |
| `fiction` | 중 (작가 고유 문체 보존 예외 필독) |
| `essay` | 중 |
| `business` | 중강 (번역투가 가장 굳어 있는 영역) |
| `newneek` | 약 (짧은 문장·문두 접속사는 이 문체의 목적이다) |
| `nominal` | **없음 — 태우지 마라** |

`nominal`에 deslop을 태우면 안 되는 이유: 교정 규칙표가 전부 `-다` 서술문을 전제로 쓰여 있다(`~이 존재한다`→`~이 있다`, 조동사 중첩, 형식주어 …). 명사형 종결을 번역투로 읽고 문장을 통째로 서술형으로 되돌린다. 개조식의 마무리는 deslop이 아니라 종결 검사·교정이 한다.

## 파일

```
SKILL.md
references/
  registers.md    문체 6종의 축 명세 + 프롬프트에 넣는 형태 + 공통 불변 규칙
  nominal.md      개조식 전용 — 규칙, 예시, 실측, 흔한 사고
scripts/
  check_endings.py  개조식 종결 검사 (표준 라이브러리만, 의존성 없음)
```

## 출처

`pdf2parallax` 스킬의 번역 파이프라인에서 쓰던 register 명세를 파이프라인과 무관하게 쓸 수 있도록 떼어 낸 것이다. 그쪽에서는 `translate.py --register <name>` 으로 같은 축을 조립해 쓰고, `nominal`의 종결 교정은 `translate.py --fix-endings-only` 가 자동으로 한다. 두 곳의 명세가 갈라지지 않게 할 것 — 고쳤으면 양쪽을 함께 본다.
