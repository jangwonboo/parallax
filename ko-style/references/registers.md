# 번역 문체 6종

"소설처럼 번역해줘"는 지시가 아니라 기분이다. 같은 프롬프트를 두 번 돌리면 다른 결과가 나온다. 그래서 register를 여섯 축의 고정값으로 정의한다. 프롬프트에는 형용사 대신 이 축을 넣는다.

> 이 문서는 축 명세다. 개조식(`nominal`)의 세부와 실측은 [`nominal.md`](nominal.md), 쓰는 순서와 검사 방법은 `../SKILL.md`.

## 축

| 축 | 값 |
|---|---|
| **종결어미** | `-다` 평서 / `-습니다` 경어 / `-요` 해요체 / 혼용 |
| **문장 분할** | 원문 유지 / 중간 / 적극 분할 / 최대 |
| **어휘 무게** | 원어 근접 / 균형 / 고유어 우선 / 한자어 우선 / 일상어 |
| **대명사** | 명시 / 부분 생략 / 대폭 생략 |
| **고유명사** | 음차 / 음차+원문병기 / 관용역 우선 |
| **존대 체계** | 해당 없음 / 인물관계표 기반 |

한국어는 영어와 달리 주어와 대명사를 계속 쓰지 않는다. `he said`, `she thought`, `it was`를 매번 "그는", "그녀는", "그것은"으로 옮기면 그 자체가 가장 큰 번역투 신호다. 대명사 축이 실질적으로 번역 품질을 가장 크게 좌우한다.

---

## `literal` — 직역

원문 대조가 목적. 읽는 맛보다 대응 관계가 우선.

- 종결: `-다`
- 문장 분할: **원문 유지.** 영어 문장 하나 = 한국어 문장 하나. 세미콜론·콜론 구조도 최대한 살린다.
- 어휘: 원어 근접. 학술 용어는 관용역이 있어도 원어 병기.
- 대명사: 명시. 생략하지 않는다.
- 고유명사: 음차 + 첫 등장 시 원문 병기 — 에이해브(Ahab)
- 존대: 해당 없음

deslop 강도: **약(S1만)**. 직역체는 의도된 것이므로 번역투를 과하게 걷어내면 목적이 사라진다.

## `fiction` — 소설

서사와 리듬이 우선. 읽는 사람이 번역서라는 걸 잊게 만드는 게 목표.

- 종결: `-다` 평서 (서술), 대사는 인물별 말투
- 문장 분할: **적극.** 영어 관계절·분사구문이 겹친 장문은 한국어에서 반드시 끊는다. 한 문장이 60자를 넘어가면 끊을 자리를 찾는다.
- 어휘: 고유어 우선. 한자어보다 순우리말 동사·형용사.
- 대명사: **대폭 생략.** 문맥으로 주어가 복원되면 쓰지 않는다. `he said` → "말했다" (인물이 명확할 때)
- 고유명사: 음차, 병기 없음. 지명은 관용역 우선.
- 존대: **인물관계표 기반.** 인물별 말투·호칭표를 먼저 확정한다. 이게 없으면 시작하지 않는다 — 대사 존대는 나중에 일괄로 고칠 수 없다.

추가 지시:
- 대사(`"..."`)는 인물의 말투를 유지한다. 교육 수준·나이·시대·관계가 말투에 드러나야 하고, 챕터가 바뀌어도 같아야 한다.
- 지시문(`he said`, `she replied`)은 한국어에서 반복이 거슬리므로 필요할 때만 남긴다.
- 원문의 문단 첫 문장이 짧고 강하면 한국어도 짧고 강하게. 리듬은 의미의 일부다.

deslop 강도: **중.** 단 아래 "보존 예외" 필독.

## `essay` — 에세이

교양서·에세이·서사 논픽션. 논지가 또렷하되 딱딱하지 않게.

- 종결: `-다`
- 문장 분할: 중간. 장문은 끊되 논리 연결이 끊기면 유지.
- 어휘: 균형. 개념어는 한자어, 서술은 고유어.
- 대명사: 생략. 단 지시 대상이 모호해지면 명시.
- 고유명사: 음차, 인명은 첫 등장 시 원문 병기
- 존대: 해당 없음

추가 지시:
- 저자의 1인칭("나는")은 필요할 때만. 영어의 `I argue that`은 한국어에서 주어 없이 "~라고 본다"가 자연스럽다.
- 수사적 질문, 도치, 삽입구 같은 저자의 문체 장치는 살린다.

deslop 강도: **중.**

## `newneek` — 뉴닉

뉴스레터 말투. 어려운 이야기를 아는 사람이 옆에서 풀어 주는 소리로 읽히게 하는 게 목표. 대중 교양서·논픽션에 맞고, 원문이 학술적일수록 효과가 크다.

- 종결: **`-요` 해요체.** 평서(`-어요`/`-예요`)와 물음(`-까요?`/`-거든요`)을 섞는다. `-다`·`-습니다`는 쓰지 않는다.
- 문장 분할: **최대.** 40자를 넘으면 무조건 끊는다. 쉼표로 잇지 말고 마침표로 끊고 접속사로 다시 시작한다.
- 어휘: **일상어.** 학술어·한자어는 쉬운 말로 바꾸되, 이름값이 있는 용어는 쉬운 말 뒤에 괄호로 남긴다 — 오목한 부분(중심와).
- 대명사: 생략. 대신 `우리`로 독자를 끌어들인다. 저자의 `I`도 `우리`나 무주어로.
- 고유명사: 음차 + 첫 등장 시 원문 병기
- 존대: 해당 없음

추가 지시:
- 접속사는 문장 맨 앞에. `따라서`·`그러므로`·`하지만`보다 `근데`·`그래서`·`그러니까`·`일단`.
- 어려운 대목은 바로 뒤에 한 마디로 푼다. 단 **원문에 있는 내용으로만** 푼다.
- 이모지·해시태그·느낌표 남발·`~읽어드릴게요` 류 상투구는 쓰지 않는다. 말투만 뉴닉이고 내용은 원문 그대로다.
- 원문의 수사적 질문은 물음표로 살리되, 없는 질문을 새로 만들지 않는다.

deslop 강도: **약.** 해요체의 입말 리듬(짧은 문장, 문두 접속사, 생략)은 번역투가 아니라 이 register의 목적이다. 세게 걸면 문체가 지워진다.

> **가장 흔한 사고 두 가지.** 하나는 원문에 없는 설명을 지어내는 것 — 말투를 흉내 내다 보면 "쉽게 말해 ~인 거죠" 뒤에 원문에 없는 비유가 붙는다. 다른 하나는 냉소를 친근함으로 바꿔 버리는 것. 저자가 비꼬는 대목을 상냥하게 옮기면 뜻이 뒤집힌다.

## `business` — 비즈니스

실용서·보고서·경영서. 정보 전달 속도가 최우선.

- 종결: `-습니다` (일반 독자용) 또는 `-다` (사내 문서용). 기본은 `-다`.
- 문장 분할: **적극.** 한 문장 한 메시지.
- 어휘: **한자어 우선.** 업계 표준 용어를 쓴다. 원어가 이미 업계 표준이면(예: 프레임워크, 레버리지) 억지 번역하지 않는다.
- 대명사: 생략
- 고유명사: 기업·제품명은 **원문 그대로.** 음차하지 않는다.
- 존대: 해당 없음

추가 지시:
- 불릿·번호 목록의 병렬 구조를 살린다. 항목 끝을 통일한다(전부 명사형 또는 전부 서술형).
- 수치·단위·연도는 절대 손대지 않는다.
- 원문이 결론을 뒤에 두더라도 문장 순서는 바꾸지 않는다. 구조 재배열은 번역이 아니다.

deslop 강도: **중강.** 비즈니스 한국어는 번역투가 가장 많이 굳어 있는 영역이라 오히려 세게 걸어야 한다.

## `nominal` — 개조식(명사형 종결)

보고서식 통독·발췌용. `business`/`literal` 바탕에 종결부만 갈아 끼운 문체다. **소설에는 쓸 수 없다** — 대사가 전부 무너진다.

- 종결: **명사형.** 문장 끝이 한자어 동사성 명사다 — `두 부분으로 구성.` `설명 제시.` `폐기 필요.`
  - `함·됨·임`은 없어도 뜻이 통하면 뗀다: 발명함→발명, 도출됨→도출, 시도일 것임→시도일 것
  - 끝맺는 명사 앞의 **조사도 뗀다**: `설명을 제시`→`설명 제시`, `폐기가 필요함`→`폐기 필요`
  - 고유어 명사형(`있음` `없음` `같음` `아님`)은 마땅한 한자어가 없을 때만
  - `했음/되었음/할 것임/고 있음`은 **시제·상을 실을 때만**: `탐구해왔음`
  - 물음표 문장만 예외이며, 그때도 `-일까?/-인가?`
- 문장 분할: 원문 유지. 단 **한 단락 안에서** 짧은 문장 축약·중복 수식 제거는 허용(단락 경계는 못 넘는다)
- 어휘: 한자어 우선
- 대명사: 생략
- 고유명사: 인명·지명은 음차+원문 병기, 기업·제품·학술지명은 원문 그대로
- 존대: 해당 없음

추가 지시:
- 계사문(A is B)을 체언 하나로 뚝 끊지 않는다. `동기는 공백.` 이 아니라 `동기는 공백에 해당.` 또는 `~로 규정됨.`
- `Suppose`·`Imagine` 은 `~해 보자` 가 아니라 `~라고 가정할 경우` 로 옮기고 문장은 명사로 끝낸다.
- 문장 **중간**의 조사·연결어미는 정상 문어체 그대로. 끝맺음만 개조식이다(전보문이 아니다).

deslop 강도: **없음 — 태우지 않는다.** 번역투 제거 규칙표가 전부 `-다` 서술문을 전제로 쓰여 있어(`~이 존재한다`→`~이 있다`, 조동사 중첩, 형식주어 …) 명사형 종결을 번역투로 읽고 서술형으로 되돌린다. 마무리는 종결 검사·교정이 대신한다 — `scripts/check_endings.py` 로 샌 문장을 찾고 그 대목만 다시 요청한다.

> **종결 규칙은 축 하나에 모아 둘 것.** 계사문·청유형 처리까지 별도 축으로 쪼개고 [절대 규칙]에까지 더했더니, 같은 36문단에서 `-다` 누출이 **1건 → 54건**으로 늘었다(시스템 프롬프트 29.4k→33.3k 토큰). 여러 자리에 흩는 것은 강조가 아니라 희석이다.

> **누출은 긴 문단의 가운데에 몰린다.** 1,200자 12문장 문단은 앞뒤가 명사형인데 중간 여섯 문장이 서술형으로 풀린다. 실측 누출률은 실행마다 0.6%~8.8%로 흔들리므로 종결 검사는 항상 돌린다. 자세한 것은 [`nominal.md`](nominal.md).

## 프롬프트에 넣는 형태

register를 아래 형태로 조립해 시스템 프롬프트에 넣는다. 축 목록을 그대로 옮겨 붙이면 된다.

```
[문체 사양]
종결어미: -다 평서형
문장 분할: 적극 — 영어 장문은 끊어라. 60자 넘는 한국어 문장은 끊을 자리를 찾아라.
어휘: 고유어 우선
대명사: 대폭 생략 — he/she/it/they를 기계적으로 옮기지 마라
고유명사: 음차, 병기 없음
존대: 아래 인물관계표를 따른다
[추가 지시]
- ...
```

축 값은 서술이 아니라 **검사 가능한 문장**으로 쓴다. "자연스럽게"는 검사할 수 없고 "60자 넘으면 끊어라"는 검사할 수 있다.

## 전 register 공통 불변 규칙

1. 문단(블록)을 합치거나 나누거나 순서를 바꾸지 않는다. 문장 분할은 자유지만 **같은 문단 안에** 머문다.
2. 숫자·연도·단위·통화·퍼센트는 그대로.
3. `[^3]` 각주 마커, `**강조**`, `*이탤릭*` 마크업은 위치를 유지한다.
4. 인용부호 안의 내용은 인용임을 유지한다(그 안에서도 register는 적용). 예외는 `nominal` 로, 대사는 인물이 실제로 한 말이라 개조식으로 바꾸지 않는다.
5. 용어집을 정했으면 그 역어를 어기지 않는다. 같은 용어가 문서 안에서 두 가지로 옮겨지는 것이 가장 흔한 사고다.
6. 원문에 없는 설명·부연·역주를 만들지 않는다. 모르면 음차하고 넘어간다.
